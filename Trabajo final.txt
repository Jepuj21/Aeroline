Introducción, punto de partida.
Situación de la empresa
Sistema web para reservación de vuelo en línea
Un dueño de una pequeña aerolínea regional está interesado en ofrecer sus servicios a
los clientes a través de un sistema web, para que estos consulten información de vuelo y
hagan sus reservaciones en línea.
Después de entrevistar a los gerentes del negocio, los representantes o agentes de
boletos y los usuarios finales del sistema, se procede a documentar claramente los
procesos del negocio y establecer el alcance del sistema. Este proceso da como resultado
un documento formal donde se detallan los requerimientos funcionales del sistema. Ese
documento es un SRS, Especificación de Requerimiento de Software
(SRS por sus siglas en
Especificación de Requerimiento de Software ([SRS] Software Requirement Specification)
1. -Los usuarios no registrados pueden entrar al sitio web de la aerolínea para ver las
informaciones de vuelo pero no pueden hacer reservaciones.
2. -Los nuevos clientes interesados en reservar vuelo pueden completar un formulario
de registro con los siguientes datos: nombre, dirección, nombre de la compañía,
número de teléfono, dirección de correo.
3. -El cliente es clasificado como corporativo o cliente minorista.
4. -El cliente puede hacer búsqueda de vuelos basado en el destino y hora de partida.
5. -El cliente puede reservar vuelo indicando el número de vuelo y número de asiento
solicitado.
6. -El sistema envía una confirmación al cliente vía correo electrónico cuando el vuelo
es reservado.
7. -Los clientes corporativos reciben millas de vuelo cuando sus empleadores
reservan vuelo.
8. -Las millas acumuladas por vuelos frecuentes son usadas para hacer descuentos a
futuras solicitudes.
9. -La reservación puede ser cancelada después de una semana con una devolución
del 80%.
10.- Los representantes o agentes de boletos pueden ver y actualizar la información de vuelo.


PASO 3.1: Definición de Actores del Sistema


* Usuario No Registrado (Visitante): Persona que accede al sitio web únicamente para consultar la disponibilidad e información de los vuelos, sin privilegios para realizar reservaciones.


* Cliente Registrado: Usuario autenticado en el sistema que puede buscar vuelos, efectuar reservaciones (especificando número de vuelo y asiento), acumular/redimir millas y gestionar cancelaciones según las políticas de la empresa.


* Agente de Boletos: Personal interno de la aerolínea con permisos para visualizar, gestionar y actualizar la información de la oferta de vuelos en el sistema.


* Gestor de mails: Sistema externo que envía los mail del sistema de reservas.

Paso 5. Escenarios a partir de los casos de uso.
Escenario para el caso de uso inicio de sesión.
Escenarios principales
1. El usuario o agente de boleta pone sus credenciales
2. La credenciales son verificadas correctamente 
3. El sistema determina qué perfil darle al usuario según la credencial
4. Entrar a todo lo que los permisos le permiten según el usuario.

Escenarios alternativo
   1. El usuario pone sus credenciales.
   2. Las credenciales son verificadas de forma incorrecta.
   3. El sistema lanza un mensaje y obliga a poner la contraseña o usuario otra vez.
Escenario para el caso de uso ver información de vuelo .
Escenarios principales
   1. El usuario sin registrar o usuario registrado entra al apartado de información de vuelo
   2. Puede ver el estado de los vuelos o asientos disponibles.
Escenario para el caso de uso registrar clientes.
Escenarios principales
   1. El usuario sin registrar llena todos los campos del formulario de registro, nombre completo, dirección, nombre de la compañía(Si aplica),RNC(Si aplica),  número de teléfono, dirección de correo.
   2. Acepta las condiciones.
   3. Y aplica los cambios dándole al botón de registrar.
   4. El sistema decide qué rol asignar al usuario si lleno o no ‘ nombre de la compañía’ y el ‘RNC’
   5. El gestor de mails le envía un correo con la información del registro.



Escenarios alternativo
   1. El usuario sin registrar llena todos los campos del formulario de registro, nombre completo, dirección, nombre de la compañía(Si aplica),RNC(Si aplica),  número de teléfono, dirección de correo.
   2. Algunos de los campos no cumplen con lo que corresponde.
   3. Se le envía un mensaje y se señala el campo incorrecto.
Escenario para el caso de uso buscar vuelos.
Escenarios principales
   1. El cliente registrado en buscar vuelo pone el destino y hora de partida.
   2. Saldrán los vuelos enlistados que coincidan en pantalla.
Escenarios alternativo
   1. El cliente registrado en buscar vuelo pone el destino y hora de partida.
   2. No coincide con ningún vuelo con estas opciones de destino y hora de partida.
Escenario para el caso de uso, reservar vuelo.
Escenarios principales 
   1. El cliente registrado selecciona un vuelo disponible en la lista de vuelos.
   2. El cliente selecciona un asiento disponible
   3. La reserva es completada con éxito
   4. El gestor de mails le envía un correo con la información de su reserva 
Escenarios alternativo cliente corporativo
   5. El cliente corporativo selecciona un vuelo disponible en la lista de vuelos.
   6. El cliente selecciona un asiento/s disponible/s
   7. El cliente selecciona el número de millas a usar para reducir el costo de su vuelo 
   8. La reserva es completada con éxito
   9. El sistema calcula y suma milla por la reserva realizada.
   10. El gestor de mails le envía un correo con la información de su reserva 
Escenarios alternativo asiento ocupado
   1. El cliente registrado selecciona un vuelo disponible en la lista de vuelos.
   2. El cliente selecciona un asiento disponible
   3. La reserva tiene un error por asiento ocupado durante el proceso. 
   4. La reserva no se procesa y obliga a seleccionar otro asiento.
Escenario para el caso de uso, cancelar vuelos.
Escenarios principales
   1. El cliente selecciona el vuelo que quiere cancelar de su lista de reservas.
   2. El cliente selecciona cancelar reserva
   3. El cliente cancela el vuelo 
   4. El cliente recibe un 80% por ciento de reembolso por cancelación anticipada.
   5. El gestor de mail le envía un correo con la información de la cancelación
Escenarios alternativo
   5. El cliente selecciona el vuelo que quiere cancelar de su lista de reservas.
   6. El cliente selecciona cancelar reserva
   7. El cliente cancela el vuelo 
   8. El cliente no recibe reembolso por cancelar con menos de 7 días antes del vuelo.
   9. El gestor de mail le envía un correo con la información de la cancelación
Escenario para el caso de uso, gestionar vuelo.
Escenarios principales
   1. El agente de boletos ver los vuelos disponibles.
   2. El agente selecciona el vuelo que quiere actualizar
   3. El agente cambia el estado del vuelo a retrasado, adelantado o a tiempo.
   4. El agente cambia el piloto
   5. El agente cambia la hora.
